### Anu Fundamentals integration

Fundamentals calls the same-origin `POST /api/anu/chat` proxy. This forwards to
Anu's `POST /api/integrations/main/chat`, where the shared constitution, Devvrats
knowledge, Gemini configuration and demo reply policy live. Do not add a Gemini
key to this project.

For local development, run Anu on `http://127.0.0.1:5173` and this project with
`npm run dev`. The proxy uses that local address automatically in development.
To use another Anu server, set the server-only `ANU_API_URL` in `.env.local` and
restart Main. For future production set `ANU_API_URL=https://anu.devvrats.in`
only after Anu has been deployed there. Nothing has been deployed by this change.

The anonymous preview keeps context in component memory, allows eight messages
per chat and 1,000 characters per message, and provides a New chat control.
Replies are generated by Anu; the example Tests tab still shows sample results.
Messages go to Anu's Gemini service. Main stores no conversation database.
The proxy's per-IP budget and Anu's aggregate demo budget are per process/isolate,
not durable quotas. Replace these with shared rate limiting before public launch;
a new chat or a new server instance is not an authentication boundary.

## Anu shared sign-in

Standalone Anu now reuses this project’s Supabase session. Local Anu links use `http://localhost:5173/` so they share localhost cookies with Main at port 3001. Production defaults to `https://anu.devvrats.in/`; override with `NEXT_PUBLIC_ANU_URL` if needed.

Registration accepts an allowlisted `next` destination and returns an already signed-in member immediately. OAuth callbacks exchange the code here, set the shared cookie, and return to that validated destination. The Anu Fundamentals CTA and non-interactive cursor-following card area open the standalone portal; embedded chat controls remain interactive.

Supabase Authentication → URL Configuration must allow Main’s `/auth/callback` URL, including `http://localhost:3001/auth/callback` for development and `https://www.devvrats.in/auth/callback` in production. Provider login/return has not yet been completed with a real member after these changes. Sabha currently uses a different Supabase project; its migration plan lives in `/Users/devvrats./Desktop/sabha/docs/shared-auth-migration.md`.

Login return behavior: Anu starts Main login with `next=http://localhost:5173/`; direct Main login defaults to Main’s `/`. `/auth/start` stores the validated destination in a short-lived HttpOnly cookie before starting OAuth; `/auth/callback` consumes it and redirects after the code exchange. Supabase must allow Main’s callback URL; the destination cookie cannot fix a malformed Supabase Site URL or redirect allowlist. Return routing changes have not been exercised through a real provider login.
